# 工作紀錄範本與填寫範例

## 建議的記錄方式

- **按專案或職責建檔，不必逐日流水帳。** 每個主要專案建立一份紀錄；每次有重要交付、技術決策、問題排除或需求變更時，新增一筆紀錄。月底或專案結束時整理成果摘要。
- **趁記憶新鮮記下事實。** 每次約花 10–15 分鐘，先記日期、情境、本人負責部分、採取的行動與結果。細節不確定時標示「待確認」，不要事後猜測。
- **分清楚個人與團隊貢獻。** 使用「我主導／我實作／我提出」描述本人工作；團隊交付則寫明「與誰合作」或「團隊完成」，避免把團隊成果寫成個人獨力完成。
- **結果盡量附證據。** 可記錄可公開的功能名稱、版本、工單編號、程式碼審查連結、發布紀錄或經確認的數據。沒有數據就寫清楚交付內容與影響，不要估算。
- **兼顧保密。** 不記錄客戶機密、帳密、個資、內部網址或未公開的營運數據；需要回想時，以專案代稱及去識別化資訊記錄。
- **為履歷與面試留素材。** 每個重要成果最後整理一行「履歷摘要」，並保留一個可在面試中說明的具體案例。

建議檔名：`YYYY-MM-專案或主題.md`，例如 `2026-11-設備管理平台.md`。若工作項目很多，可在檔案內以日期作為小標題。

## 填寫範例：既有 JavaScript 系統遷移至 React

> 本範例依現有履歷內容整理，適合作為格式示範；它不是新增的工作事實。專案確切期間、技術細節、個人負責邊界和量化成果仍需本人確認後再採用。

### 基本資料

- 公司／團隊：緯創軟體股份有限公司
- 職稱／角色：高級工程師；履歷列職稱為軟體工程師
- 專案期間：任職期間內；專案起訖日期待確認
- 履歷所列任職期間：2021/09–2026/04
- 合作對象：UI/UX 設計師、後端工程師；其他角色待補
- 使用技術：JavaScript、React；其餘遷移專案技術待確認

### 背景與目標

- 維護既有系統前端，並將舊版 JavaScript 系統逐步遷移至 React 架構。
- 系統需整合多個廠區的差異化需求。
- 舊系統的具體維護痛點、使用者需求及專案啟動原因：待補，請依實際情況描述。

### 我的責任範圍

- 履歷記載由本人主導系統遷移與重構。
- 負責逐步遷移並驗證舊版功能，建立模組化元件架構，並設計可配置化／可抽象化邏輯以處理多廠區差異。
- 與 UI/UX 設計師及後端工程師協作，統整跨廠區需求。
- 具體負責的模組、決策權限及團隊分工：待補。

### 採取的行動

1. 將既有 JavaScript 系統逐步遷移至 React 架構。
2. 遷移過程中驗證舊版功能，確認既有功能完成轉換。
3. 建立模組化元件架構，支援後續維護與擴充。
4. 與 UI/UX 設計師及後端工程師統整不同廠區需求，設計可配置化的處理方式。
5. 將多廠區差異抽象化，降低以客製化分支維護的需要。

> 每項行動的實際順序、採用的測試方式、遇到的技術難題與解法，請補上親身經歷，不要只照抄範例。

### 結果與證據

- 履歷記載：React 系統完成遷移後，舊系統下架。
- 履歷記載：系統推廣至多個廠區，包含海外廠區，並支援不同廠區差異化需求。
- 履歷記載：模組化及可配置化設計用於提高可維護性、可擴充性並降低客製化分支維護成本；實際影響範圍可再補證據。
- 量化結果：目前沒有可確認的數據。若要補充，先確認廠區數、遷移模組數、客製分支變化或維護工時的來源及計算方式。
- 可追溯證據：可補上已去識別化的專案文件、工單、程式碼審查或發布紀錄；勿放入客戶機密。

### 履歷摘要範例

主導既有 JavaScript 系統逐步遷移至 React，透過功能驗證與模組化元件架構完成舊系統下架；並與 UI/UX 及後端團隊整合多廠區需求，以可配置化設計支援不同廠區的差異。
